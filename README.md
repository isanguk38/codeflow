# CodeFlow

보기 쉽고 사용하기 간편한 무료 Git 형상관리 데스크톱 툴 (Electron).
IntelliJ 에 내장된 Git 도구의 사용감을 참고해서 만들었습니다.

## 실행

필요한 것: [Node.js](https://nodejs.org) 18 이상, [Git for Windows](https://git-scm.com)

```bash
npm install
npm start
```

설치 파일(.exe) 만들기:

```bash
npm run dist
```

`release/` 폴더에 설치형(NSIS)과 포터블 exe 가 생성됩니다.

## 주요 기능

| 화면 | 기능 |
| --- | --- |
| 커밋 | 변경 파일 목록(체크박스로 커밋 대상 선택), 나란히/통합 Diff, 단어 단위 강조, 커밋 / 커밋 후 Push, Amend, 파일별 되돌리기(Rollback), .gitignore 추가 |
| 히스토리 | IntelliJ 방식 표시(커밋 날짜순, 병합 커밋은 회색, origin & master 배지), 보기 메뉴에서 브랜치별 정렬로 변경 가능, 브랜치 그래프, 브랜치/파일별 필터, 메시지 검색, 커밋 상세와 파일별 Diff, Revert, Reset(Soft/Mixed/Hard), 체리픽, 태그, 여기서 브랜치 만들기 |
| 브랜치 | 툴바 브랜치 팝업: 검색, 새 브랜치, 체크아웃(원격 브랜치는 자동 추적 브랜치 생성), 병합, 리베이스, 이름 변경, 삭제 |
| 충돌 | 충돌 파일 목록에서 내 것/상대 것 적용, 3단 병합 도구(내 변경 / 결과 / 상대 변경), 병합·리베이스 계속/중단 |
| 스태시 | 작업 중인 변경 보관, 적용, 꺼내기, 삭제 |
| 병합 | 병합 방식 선택: 기본 / 항상 병합 커밋(--no-ff) / 하나로 합치기(--squash) / Fast-forward 만(--ff-only), 병합 커밋 메시지 편집 |
| 원격 | Fetch, Pull(병합 또는 리베이스), Push 전 커밋 목록 확인, 강제 Push(--force-with-lease) |
| 코드 | VS Code 편집기(Monaco)로 파일 보기·수정·저장, 파일 탐색기(새 파일/폴더, 이름 변경, 휴지통 삭제, Git 상태 표시), 파일 탭, 줄 번호 옆 Git 변경 표시, TypeScript/JavaScript·Python·Java(언어 팩) 오류 표시·자동 완성·마우스 올림 정보·정의로 이동(F12)·서식 정리, 아래쪽 터미널 패널(PowerShell / 명령 프롬프트 / Git Bash, 여러 개, 프로젝트 폴더에서 시작) |

스마트 모드: 로컬 변경 때문에 체크아웃/Pull 이 막히면 변경 사항을 자동으로 보관했다가 작업 후 다시 적용합니다.

### 고급 기능

| 기능 | 위치 |
| --- | --- |
| 여러 프로젝트 탭 | 상단 탭 바. ＋ 로 새 탭, Ctrl+Tab 전환, Ctrl+W 닫기, 드래그로 순서 변경. 열어 둔 탭은 다음 실행 때 복원 |

| 대화형 리베이스 | 히스토리 → 커밋 우클릭 → `여기부터 커밋 편집`. 순서 변경, 메시지 수정, 합치기(squash/fixup), 삭제 |
| 여러 커밋 한 번에 | 히스토리에서 Ctrl/Shift+클릭으로 여러 개 선택 → 우클릭: 체리픽, Revert, 하나로 합치기(합칠 커밋 확인 + 메시지 입력), 두 커밋 비교 |
| 여러 커밋 변경 파일 · 자원 리스트 | 히스토리에서 커밋 여러 개를 고르면 아래에 선택한 커밋 목록과 **합친 변경 파일(중복 제외, 바뀐 횟수 ×N)** 이 보이고, 파일을 누르면 선택한 커밋들 전체의 변경을 Diff 로 봅니다. `⬇ 엑셀` 또는 파일 우클릭 → `엑셀로 내보내기` 로 자원 리스트(구분·경로·파일명·폴더·확장자·커밋·메시지·작성자·날짜 + 커밋 목록 시트)를 .xlsx 로 저장 |
| 이슈로 히스토리 거르기 | 이슈 목록에서 이슈를 누르면 그 이슈 번호(#N, N-브랜치)를 언급한 커밋만 히스토리에 보임. 다시 누르거나 ✕ 로 해제, 두 번 클릭(ⓘ)은 이슈 내용 |
| Blame | 커밋 화면 파일 우클릭 → `Blame`, 또는 히스토리 상세 파일 우클릭 → `이 리비전에서 Blame` |
| Reflog | 히스토리 상단 `↺ Reflog`. 잃어버린 커밋을 브랜치로 되살리기 / 리셋 |
| 브랜치 여러 개 업데이트 | 히스토리 왼쪽 로컬 브랜치를 Ctrl+클릭 / Shift+클릭으로 여러 개 선택 → 우클릭 `모두 업데이트 (Pull)`. 체크아웃하지 않은 브랜치도 하나씩 우클릭 → `업데이트 (Pull, 체크아웃 없이)` (Fast-forward 만, 로컬에만 있는 커밋이 있으면 건너뜀). 체크아웃은 우클릭 메뉴에서만 (더블클릭 없음) |
| 프로젝트 전체 찾기 | Ctrl+Shift+F 또는 탐색기 🔍. IntelliJ 의 Find in Files 처럼 파일·폴더 이름과 파일 내용을 함께 찾고, 아래에 미리 보기. Enter 로 그 줄을 열기. 파일 마스크(`*.java, !*.min.js`), 폴더 범위(탐색기 폴더 우클릭 → 이 폴더에서 찾기). .gitignore 로 무시한 파일은 제외 |
| 이슈 | 히스토리 왼쪽 아래 `이슈` 패널 (GitHub / GitLab, 자체 설치 GitLab 포함). 열림·닫힘·내 담당, 검색(#번호), 아래로 내리면 30개씩 더. 이슈를 누르면 상세 + `웹에서 열기` / `커밋 메시지에 번호 넣기` / `이 이슈로 브랜치 만들기`. 인증은 Git 에 저장된 로그인 정보를 먼저 쓰고, 안 되면 개인 액세스 토큰을 붙여 넣음 (Windows 계정으로 암호화 저장) |
| 브랜치 골라 보기 | 히스토리 왼쪽 `모든 브랜치`(기본, VS Code 의 All) 옆 `☐ 골라 보기` 를 누르면 체크박스가 나타나 원하는 브랜치들만 묶어 보기. 그냥 클릭하면 그 브랜치만. 원격이 지워진 로컬 브랜치는 `원격 삭제됨` 표시 |
| 브랜치·커밋 비교 | 브랜치 메뉴 → `현재 브랜치와 비교`, 커밋 우클릭 → `HEAD 와 비교` |
| 일부 파일만 Stash | 파일 우클릭 → `이 파일만 보관`, 또는 체크한 파일만 보관 |

## 구조

```
src/
  main/main.js       Electron 메인 프로세스 (창, IPC)
  main/git.js        git CLI 래퍼 (기본 Git 작업)
  main/git-extra.js  고급 Git 작업 (대화형 리베이스, Blame, Reflog, 비교)
  main/channels.js   렌더러에서 호출 가능한 Git 함수 목록
  main/files.js      코드 화면 파일 작업
  main/lsp.js        언어 서버 실행/중계 (TypeScript 는 앱에 포함)
  main/terminal.js   터미널 (ConPTY 로 셸 실행)
  main/python.js     Python 인터프리터 찾기
  main/javapack.js   Java 언어 팩 설치/제거, 설치된 JDK 찾기, 프로젝트 Java 버전 읽기
  preload.js         window.api 로 안전하게 노출
  renderer/          화면 (HTML/CSS/바닐라 JS 모듈)
```

서버가 필요 없습니다. 모든 작업은 PC 에 설치된 `git` 을 실행해서 처리하고, GitHub 같은 원격 저장소와는 git 이 직접 통신합니다. 로그인은 Git for Windows 에 포함된 Git Credential Manager 가 처리합니다.

## 코드 화면의 오류 표시 (언어 서버)

VS Code 와 같은 방식으로 내 PC 에서 언어 서버를 실행해 오류를 표시합니다. 언어 서버는 모두 앱에 포함되어 있어 따로 설치할 것이 없습니다.

| 언어 | 언어 서버 | 버전 기준 |
| --- | --- | --- |
| TypeScript / JavaScript | typescript-language-server | 프로젝트의 `node_modules/typescript`, 없으면 앱에 포함된 TypeScript |
| Python | Pyright (Pylance 의 무료 엔진) | 상태 표시줄 `🐍 Python` 에서 고른 인터프리터. 처음엔 프로젝트의 `.venv`/`venv` → 시스템 Python 순으로 자동 선택. 열린 파일만 검사해 큰 프로젝트에서도 가볍게 동작 |
| Java | Eclipse JDT LS (VS Code Java 와 같은 엔진) — **언어 팩** | 아래 'Java 프로젝트 구조' 참고. Java 프로젝트 탭을 열거나 고르면 미리 실행(파일을 열면 바로 검사), 다른 탭으로 옮기고 열린 Java 파일이 없으면 5분 뒤 또는 프로젝트 탭을 닫으면 종료, 메모리 최대 1GB, 프로젝트 색인 저장으로 두 번째부터 빠르게 시작. 오류 메시지는 영어 |

### Java 프로젝트 구조 (IntelliJ 의 Project Structure 와 같은 역할)

Java 파일을 처음 열면 CodeFlow 가 프로젝트를 분석해서 검사 기준을 정합니다.

1. `pom.xml` (Maven) / `build.gradle` (Gradle): 적힌 Java 버전에 맞는 JDK 로 검사하고, 의존성 라이브러리를 받아 자동 완성에 포함
2. 빌드 파일이 없는 프로젝트: 폴더 전체를 분석
   - **소스 폴더**: `.java` 파일의 `package` 선언과 폴더 위치로 찾음 (예: `JavaSource/com/acme/A.java` + `package com.acme;` → `JavaSource`)
   - **라이브러리**: 프로젝트 안의 모든 `.jar` (`WEB-INF/lib`, `lib`, `jars` 등 위치 무관, `target`·`build`·`out`·`bin` 같은 결과물 폴더 제외)
   - `.classpath`(Eclipse) 가 있으면 거기 적힌 Java 버전·jar·소스 폴더도 합침 (`.idea` 는 읽지 않음). 단, 언어 서버가 Eclipse 프로젝트로 직접 가져오지는 않으므로 `.project`·`.classpath`·출력 폴더(`build/classes` 등)는 건드리지 않음
   - **JDK**: 직접 고른 JDK → 설치된 가장 최신 JDK
3. 분석 결과와 직접 바꾼 설정은 프로젝트의 `.codeflow/java.json` 에 저장됩니다 (`.git/info/exclude` 에 자동 등록돼 Git 변경 사항에 나오지 않음)

상태 표시줄 `☕ Java` → **🧱 프로젝트 구조** 에서 JDK 변경, 소스 폴더 추가/제외, jar 체크 해제(검사에서 빼기), 프로젝트 밖 jar 추가(예: Tomcat 의 `servlet-api.jar` → `+ 폴더의 jar 모두 추가`), 다시 분석을 할 수 있습니다. 적용하면 언어 서버를 다시 시작하지 않고 바뀐 부분만 1~2초 안에 다시 검사합니다 (IntelliJ 처럼 색인을 처음부터 만들지 않음).

- JDK 는 `C:\Program Files` 의 Java 폴더, IntelliJ 가 받은 `~/.jdks`, IntelliJ 에 등록된 JDK 목록, 직접 고른 폴더에서 찾습니다.
- Java 1.7 이하 JDK 를 고르면 클래스·함수는 그 JDK 기준이지만, 문법 검사는 검사 엔진이 1.7 이하를 지원하지 않아 더 높은 버전 기준입니다.
- 상태 표시줄 `☕ Java` 위에 마우스를 올리면 언어 서버가 **실제로 적용한** Java 버전과 JDK 경로, jar 개수, 소스 폴더가 보입니다.
- 프로젝트 폴더에 `.project`/`.classpath`/`.settings` 를 만들지 않습니다. (Maven 빌드 결과 `target/` 은 IntelliJ·VS Code 와 같이 생김)

## AI 패널 (오른쪽, `✦ AI` 또는 Ctrl+Shift+A)

VS Code 의 Claude Code / Codex 확장처럼 외부 AI 를 연결해서 씁니다.

1. 패널 위쪽에서 AI 선택: **Claude Code** (Anthropic) 또는 **Codex** (OpenAI)
2. 설치되어 있지 않으면 `설치` — Claude Code 는 공식 설치 프로그램, Codex 는 공식 npm 패키지의 Windows 실행 파일을 사용자 폴더에 설치 (관리자 권한·Node.js 불필요)
3. 로그인 — 브라우저가 열리고 Claude 계정(Pro/Max·Console) 또는 ChatGPT 계정으로 로그인. 로그인 정보는 각 도구가 직접 보관
4. 대화: AI 는 지금 보고 있는 프로젝트 폴더에서 실행되고, 프로젝트 탭마다 대화가 따로입니다
- **업데이트**: Claude Code 는 스스로 자동 업데이트(다음에 깨울 때부터 새 버전). CodeFlow 가 설치한 Codex 는 앱을 켤 때·6시간마다 새 버전을 확인해 알려 주고, `⋯` 메뉴에서 `Codex x.y.z 으로 업데이트` / `이전 버전으로 되돌리기` (이전 버전 하나를 남겨 둠)
- **최근 대화 이어 가기**: 프로젝트를 열면 그 프로젝트에서 가장 최근에 나눈 대화를 불러와 이어 갑니다 (새로 시작하려면 `＋`)
5. **미리 깨우기**: 앱을 켤 때·프로젝트 탭을 바꿀 때·AI 를 바꿀 때, 고른 AI 를 그 프로젝트에서 미리 실행해 둡니다 (입력창 위 `깨우는 중… → 준비됨`). 첫 질문부터 바로 답하고, 한 번 깨운 AI 는 계속 켜 두어 다시 바꿔도 기다리지 않습니다
6. **AI 를 바꿔도 대화는 그대로**: 대화 도중 위쪽에서 Claude ↔ Codex 를 바꾸면, 새 AI 에게 그동안의 대화(다른 AI 의 답변과 한 작업 포함)를 넘겨 주고 같은 대화를 이어 갑니다. 대화는 CodeFlow 가 프로젝트마다 저장하고 `🕘` 에서 다시 열 수 있습니다 (각 답변에 어느 AI 가 답했는지 표시)

화면
- 답변 중 진행 상태: `생각 중 · 토큰 · 초`, `답변 작성 중`, `실행 중: 파일 수정 ...`, `허용을 기다리는 중`
- 입력창 아래: 모델 선택(기본값 / Opus / Sonnet / Haiku / Fable — 다음 질문부터 같은 대화로 적용), `컨텍스트 %`(누르면 지금 정리 `/compact`, 가득 차면 자동 정리), 플랜 사용량 `세션 %` · `주간 %`(마우스를 올리면 초기화 시각)
- `＋` 새 대화(지금 대화는 기록에 남음), `🕘` 지난 대화 목록에서 골라 이어서 대화, `⋯` 에서 연결된 MCP 서버·claude.ai 커넥터 상태
- 첨부: `📎` 버튼, 이미지 붙여넣기(Ctrl+V), 패널에 끌어다 놓기. 이미지·PDF 는 내용을 그대로 보내고(큰 이미지는 1568px 로 줄임), 그 밖의 파일은 경로를 알려 AI 가 직접 읽음. 한 번에 10개까지
- **문서(엑셀·PPT·워드·PDF·CSV 등)**: 저장 위치를 말하지 않으면 AI 가 프로젝트에 넣지 않고 임시 결과물 폴더에 만든 뒤, 대화창에 미리보기와 함께 `어디에 저장할까요?` (`저장 위치 선택…` / `다운로드 폴더에 저장` / `나중에`) 를 띄웁니다. 경로를 말하면 그 경로에 바로 만듭니다. 명령(파이썬 등)으로 만든 파일도 카드로 표시하고, 문서는 `열기` 를 누르면 엑셀·파워포인트 등 연결된 프로그램으로 열립니다
- AI 가 만들거나 고친 파일은 대화 안에 파일 카드로 표시 (이미지는 미리보기). `보기/열기` · `폴더`(탐색기) · `저장`(다른 이름으로 저장, 다운로드 폴더 기본). 코드 화면에서도 이미지 파일은 그림으로 열리고, SVG 는 `코드로 열기` 가능
- AI 가 파일을 고치면 열린 파일과 변경 목록을 바로 다시 읽고, 편집기의 예전 내용으로 덮어쓰지 않도록 저장 전에 확인

AI 가 할 수 있는 것
- 코드 질문·수정·실행 (파일 수정과 명령 실행은 대화 안의 `허용 / 거부` 카드로 먼저 묻습니다)
- CodeFlow 사용법 안내 (앱에 포함된 CodeFlow 화면 설명서를 AI 에게 함께 넘김)
- CodeFlow 직접 조작 (CodeFlow 가 내 PC 안에서만 열리는 도구 서버(MCP)를 제공): 터미널 패널에서 명령 실행·출력 읽기, 파일 열기, 화면 이동, Git 상태 보기, 열린 프로젝트 탭 목록·탭 전환
- 여러 프로젝트: CodeFlow 에 탭으로 열린 프로젝트 폴더는 모두 AI 가 읽고 수정할 수 있음 ("열린 프로젝트 뭐 있어?", "admin-web 의 ~ 고쳐줘")

## 자동 업데이트

설치형 CodeFlow 는 시작할 때, 1시간마다, 그리고 창으로 돌아왔을 때 마지막 확인이 10분 넘게 지났으면 GitHub 최신 릴리즈를 확인합니다(ERD 앱과 같음). 새 버전이 있으면 "새 버전이 나왔습니다" 창과 상단 `⬇ 업데이트` 버튼이 나타나고, **지금 업데이트** 를 누르면 설치 파일을 내려받아 실행한 뒤 앱이 닫힙니다(설치가 끝나면 새 버전으로 열림). **나중에** 를 누르면 그날은 다시 묻지 않습니다. 설정 → `업데이트 확인` 으로 직접 확인할 수도 있습니다. 포터블 버전은 릴리즈 페이지를 열어 줍니다.

## 릴리즈

```bash
git tag v0.1.0
git push origin v0.1.0
```
